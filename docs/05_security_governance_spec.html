Security & Governance Spec

로컬 고신뢰 수집을 안전하게 운영하기 위한 collection profile, redaction, retention, export governance를 정의한다.

SecurityRedactionLocal-first

01Security Stance

이 서비스는 개인 로컬 환경에서 고신뢰 데이터를 수집한다. collection level은 높아도 되지만, 수집된 데이터에는 source code, command output, token, private path, secrets가 포함될 수 있으므로 local binding, redaction, retention, export control은 제품 핵심 요구사항이다.

기본 방침: 높은 수집 수준은 허용하되, 네트워크 노출과 raw export는 보수적으로 제한한다. 로컬 insight를 위한 수집과 외부 전송 가능성을 엄격히 분리한다.

02Collection Profiles

현행 동작: 아래 4단계 profile 분류는 설계 분류이며, profile 선택 기능은 제공하지 않는다. 서비스는 단일 고정 프로파일로 동작하고, 모든 API 응답 meta.collection_profile에 상수 "local_transcript_slice1"(src/model/meta.rs)이 들어간다. 실제 수집 범위는 transcript + tool I/O + OTel traces/metrics/logs + hook payload + diff hunk + verification output으로 local_full_evidence에 해당한다. raw_api_body는 수집하지 않는다.
ProfileIncludesDefaultRisk
metadata_onlytimestamps, source type, ids, status onlyNoLow
local_transcripttranscript messages, tool call/result metadataNoMedium
local_full_evidencetranscript, tool input/output, OTel metrics/logs/traces, hook payloads, file/git diff hunks, verification outputYes — 실제 수집 범위High but local
raw_api_bodyraw model/API request and response bodiesNo — 수집하지 않음Very high

Default

local_full_evidence가 기본이며 실제 수집 범위다. raw_api_body는 수집하지 않으며, 도입한다면 별도 explicit opt-in으로 둔다.

Reason

로컬 insight 품질을 위해 tool I/O, OTel trace, diff hunk가 필요하다. raw API body는 replay 이상의 민감도를 가진다.

03Local Access Boundary

Bind

기본 127.0.0.1:7878 (wimcc serve --bind --port). 다른 주소 바인딩은 explicit --bind 설정으로만 가능하다.

Origin validation /mcp만

/mcp(Streamable HTTP)는 localhost Origin allowlist를 검증한다. Origin header가 없는 요청(curl류)은 허용한다. /v1/* Pull API에는 Origin 검증이 없다 — localhost bind + (옵션) bearer token이 경계.

Local token 기본 off

인증 default는 --auth off(단일 사용자 dev 가정). wimcc serve --auth on 시 /v1/* GET endpoint + /mcp 요청에 Authorization: Bearer <token>을 요구한다(상수 시간 비교). 단 /v1/stream(SSE)은 auth 라우터 밖이라 항상 무인증이다 — 예외 전체 목록은 아래 callout. Token 파일: macOS ~/Library/Application Support/wimcc/token · Linux ~/.config/wimcc/token (mode 0600, WIMCC_CONFIG_DIR로 override). --print-token / --rotate-token 제공.

무인증 예외: ingest용 POST endpoint(/otel/v1/traces|metrics|logs, /hooks/v1/events), GET /v1/stream(SSE), 정적 SPA는 --auth on이어도 token을 요구하지 않는다 — loopback bind가 경계다. GET /v1/health는 security: {auth_required, retention_profile} 블록으로 현재 상태를 노출한다.

04Redaction Policy

Redaction gate: ingest 시점에 동작한다 — raw_event 저장 전에 payload를 마스킹하므로 DB에는 마스킹된 텍스트가 저장된다(transcript·hook·OTel ingest 경로 모두, src/ingest/store.rs·hook.rs·otel.rs → src/security/redaction/engine.rs). rule pack은 rule_pack@v1 — 정확히 11개 규칙(추가 시 _v2 bump): api_key_anthropic.v1, api_key_openai.v1, github_pat.v1, aws_access_key_id.v1, aws_secret_access_key.v1, bearer_token.v1, private_key_pem.v1, email.v1, phone.v1, korean_rrn.v1, high_entropy_heuristic.v1(flag-only — 마스킹하지 않고 has_unredacted_sensitive_payload만 set). 이벤트별 manifest는 raw_event.redaction_manifest에 저장되고, API 응답 meta.redaction_summary로 집계되며, MCP resources/read는 annotations.redaction_policy/redaction_summary를 싣는다.
범위: redaction은 위 11개 규칙 기반 pattern masking이 전부다. sensitive path prefix redaction은 적용하지 않으며, export 전 review 흐름은 없다(export bundle 자체를 제공하지 않는다 — §06).

05Retention and Deletion

Retention 동작: 기본값은 none — 아무것도 삭제하지 않는다(무기한 로컬 보존). wimcc serve --retention-profile none|default|strict로 선택하며, 활성 시 6시간 주기 background sweep가 돈다. 삭제된 resource는 retention_tombstone에 기록되고 조회 시 410 Gone(RESOURCE_GONE)을 반환하며, sweep마다 audit row retention.deleted가 남는다. /v1/health의 security.retention_profile로 활성 프로파일을 확인할 수 있다.
sweep 적용 범위 (2026-06-11 전면 구현): sweep는 네 data class 전부를 단일 트랜잭션으로 처리한다. raw payload는 row 삭제가 아니라 payload scrub — skeleton row(source_uri·line_no·sha)는 남는다. observed_event.raw_event_id FK(raw가 normalized보다 먼저 만료되므로 row 삭제는 FK 위반)와 ingest dedup triple을 보존해 ingest --all 재실행이 만료된 내용을 부활시키지 못하게 하기 위함이다. normalized·Signal은 세션 단위로 만료된다: 세션의 최신 observed_at이 normalized cutoff보다 오래되면 그 세션의 observed_event·diff_hunk·verification_run·usage_facet·signal row 전부가 삭제된다. tombstone 입자: raw_event_id·session_id·signal_id·verification_run_id (per-event tombstone은 쓰지 않는다 — 세션당 1만+ 이벤트 × 영구 보존(DEV-S19-04)이라 만료된 개별 event 조회는 410이 아닌 404를 받는다).

06Export Governance

현행 상태: export bundle 기능(POST /v1/export-bundles)은 제공하지 않는다 — 데이터가 로컬을 떠나는 경로는 없다. 이 섹션은 governance 원칙이며, 도입한다면 아래 흐름과 제약을 따른다.

Export는 로컬 owner action이다. 외부 service가 domain object에 쓰기 작업을 하는 방식이 아니다. (read-only API 원칙의 유일한 write 예외.)

Select resourcesignal/session/lineage
Preview evidencenodes · raw refs
Apply redactionmanifest required
Review warningsensitive payload check
Create bundlelocal file + hash
Consume externallyoutside responsibility
Export bundle must not include: patch, hook installation script, Claude settings change, memory write, skill scaffold, command that mutates project state.

07Audit Events

08Provenance and Integrity

{
  "provenance": {
    "schema_version": "provenance.v1",
    "source_version": "claude_code_source_unknown",
    "parser_version": "otel_parser.v1",
    "pipeline_version": "whats-in-my-cc_pipeline.v1",
    "created_at": "2026-05-19T09:12:00+09:00",
    "evidence_refs": ["raw_evt_001", "evt_002"]
  },
  "integrity": {
    "content_hash": "sha256:...",
    "manifest_hash": "sha256:..."
  }
}

evidence_refs는 raw/observed event id를 가리킨다. Signal의 provenance는 {detector, version: "L1", rule_pack} 형태로 deterministic detector 출처를 기록하며 — 모든 산출은 deterministic L1이다 — evidence_refs 없는 Signal은 만들지 않는다.
