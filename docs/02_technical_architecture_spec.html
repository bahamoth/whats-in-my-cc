01Architecture Overview

아키텍처는 로컬에서 실행되는 observation-to-insight pipeline이다. 모든 source layer는 raw evidence store에 보존되고, normalized event와 graph/insight store는 UI·Pull API·MCP Streamable HTTP가 공유한다.

02Local Runtime Boundary

Process model

단일 로컬 서비스 프로세스가 collector, pipeline, UI server, Pull API server, MCP Streamable HTTP endpoint를 제공한다. 구현 시 분리는 가능하지만 logical boundary는 하나로 정의한다.

Network model

기본은 127.0.0.1 binding이다. LAN 노출은 explicit setting으로만 허용한다.

Storage model

raw evidence, normalized event, graph, insight, export manifest를 분리된 logical store로 둔다.

Trust model

사용자가 소유한 로컬 데이터를 대상으로 한다. 외부 client는 read-only consumer다.

Commit SHA는 verification marker로 사용되지 않는다 — verification semantics는 (a) Bash tool_result(test 명령의 stdout/exit), (b) hook PreToolUse/PostToolUse verification command, (c) OTel verification span에서만 도출된다.

04Pipeline Stages

Stage 1 · Capture

Raw source event를 수집하고 source_uri, offset, capture timestamp, collection profile을 부여한다.

Stage 2 · Redaction Gate

secret/credential/PII/path rule을 적용하고 raw payload의 redaction manifest를 만든다.

Stage 3 · Normalize

source별 parser가 ObservedEvent로 변환한다. OTel metrics/logs/traces는 telemetry facet을 가진다.

Stage 4 · Merge

tool_use_id, trace_id, span_id, prompt.id, file_path 등으로 logical node를 병합한다.

Stage 5 · Edge Build

deterministic edge를 우선 생성한 뒤 inference rule로 causal edge를 생성한다.

Stage 6 · Derive Products

context map, file lineage, verification map, finding, root-cause hypothesis를 생성한다.

Stage 7 · Serve

UI, Pull API, MCP Streamable HTTP가 동일 resource model을 읽는다.

07OTel Integration Details

OTel data는 단순 metric dashboard용이 아니라 graph identity와 quality signal을 제공한다.

Metrics

token, cost, cache, active time, model usage, tool counts. Aggregated by session/project/model.

Logs / Events

API request/error, tool result, lifecycle event. Transcript/hook와 cross-reference.

Traces

span hierarchy, parent-child relation, latency attribution. Graph edge의 backbone.

Resource attributes

service.name, session.id, project, user-local context. Access control and grouping.

08Serving Architecture

⚠ 2026-06-04 변경 (PR #33): Local UI의 메세지·디테일·raw 뷰는 Graph Store(GraphNode/facet-fold)를 읽지 않는다. Normalized Event Store(ObservedEvent) + Raw Evidence Store를 correlation 키(tool_use_id/request_id)로 직접 읽는다. Stage 4 Merge의 graph node·facet-fold(Stage 3의 telemetry facet과 다름)는 Stage 5 Edge Build(causal inference)와 /graph Pull API/MCP 전용이다. 상세: implementation-notes.html#event-first-redesign.

Local UI

Human-first exploration. Uses the same internal read service as API.

Pull API

HTTP GET endpoints for sessions, graph, findings, lineage, context, export manifest.

MCP Streamable HTTP

Single local MCP endpoint exposes resources and read-only tools for MCP clients.

Boundary: serving layer never applies improvements. No CLAUDE.md update, no hook install, no skill generation, no memory write.
