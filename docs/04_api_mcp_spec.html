Pull API & MCP Streamable HTTP Spec

외부 시스템이 로컬 insight resource를 읽기 위한 Pull API와 MCP Streamable HTTP 계약을 정의한다.

Pull APIMCP Streamable HTTPread-oriented

01Integration Principles

  • Read-oriented: 외부 client는 insight resource를 읽는다. correction, label, status write는 제공하지 않는다.
  • Same domain model: UI, Pull API, MCP는 같은 resource schema를 사용한다.
  • Local-first security: 기본 endpoint는 localhost에만 bind한다.
  • Streaming where useful: MCP Streamable HTTP는 long-running ingest/analysis 상태와 finding 생성 이벤트를 stream할 수 있다.
용어: MCP 공식 명칭은 Streamable HTTP transport다. 본 문서에서는 사용자의 표현인 “MCP streaming http”를 이 transport로 해석한다.

02Serving Surface

Local UI

브라우저 기반 사람이 보는 화면. 모든 detail은 API-backed view model이 아니라 domain resource로부터 렌더링된다.

Pull API

HTTP JSON API. GET 중심. export bundle 생성 같은 owner-only local action은 별도 보호.

MCP Streamable HTTP

AI client나 tool client가 resources와 read-only tools를 통해 insight를 조회한다.

05MCP Streamable HTTP Contract

06Streaming Events

07Auth, Origin, and Local Binding

  • 기본 bind: 127.0.0.1.
  • all-interface bind는 explicit setting과 UI warning 필요.
  • MCP Streamable HTTP endpoint는 Origin header를 검증한다.
  • local auth token을 기본으로 요구한다. token은 UI에서 rotate 가능해야 한다.
  • raw evidence endpoint는 redaction policy를 항상 반환한다.

10피드백 필요 사항

  1. Pull API에서 owner-only POST /v1/export-bundles를 허용할지, export는 UI/CLI에서만 만들지 결정 필요.
  2. MCP endpoint가 streaming event를 기본 활성화할지, client capability negotiation 후 활성화할지 결정 필요.
  3. API response의 기본 evidence depth를 node-level까지만 할지, edge/raw source refs까지 포함할지 결정 필요.
