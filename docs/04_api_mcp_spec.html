Pull API & MCP Streamable HTTP Spec

외부 시스템이 로컬 insight resource를 읽기 위한 Pull API와 MCP Streamable HTTP 계약을 정의한다.

Pull APIMCP Streamable HTTPread-oriented

01Integration Principles

  • Read-oriented: 외부 client는 insight resource를 읽는다. correction, label, status write는 제공하지 않는다. 모든 Pull API endpoint는 GET이다 (예외: collector ingest POST — 외부 write가 아니라 로컬 telemetry 수집 입력).
  • Same domain model: WebUI, Pull API, MCP는 같은 resource schema(ObservedEvent · Signal · VerificationRun · DiffHunk · usage aggregate)를 사용한다.
  • Local-first security: 기본 endpoint는 127.0.0.1에만 bind한다.
  • Event-first: 모든 조회는 ObservedEvent + correlation 키(tool_use_id/request_id/turn_id/message_id)에 직접 기반한다. graph node/edge 레이어는 존재하지 않는다.
  • Deterministic insight: signal은 deterministic L1 detector가 생성하며 severity/confidence 같은 judgment 필드가 없다. LLM judge 서브시스템은 존재하지 않는다.
용어: MCP 공식 명칭은 Streamable HTTP transport다. 본 문서에서는 사용자의 표현인 “MCP streaming http”를 이 transport로 해석한다.

02Serving Surface

Local WebUI

브라우저 기반 React SPA (rust-embed로 서버에 내장). 같은 Pull API + SSE를 소비해 event-first replay와 insight strip을 렌더링한다.

Pull API

HTTP JSON API. 전부 GET read-only. write endpoint 없음.

MCP Streamable HTTP

/mcp 단일 endpoint. AI client가 resources와 read-only tools 4종으로 insight를 조회한다.

Collectors (입력면): 같은 서버가 OTLP/HTTP receiver(POST /otel/v1/traces|metrics|logs)와 hook receiver(POST /hooks/v1/events)를 함께 연다. 이는 telemetry 수집이며 read-only 원칙의 예외가 아니다 — domain resource를 외부에서 수정하는 경로가 아니다.

Common response envelope

대부분의 endpoint는 {meta, data} envelope을 반환한다 (src/model/meta.rs의 Envelope<T>). 위 표의 Envelope 열이 예외를 표시한다: /v1/health는 bare JSON, metrics/signals/detectors/audit는 {data}만 반환한다.

{
  "meta": {
    "schema_version": "0.5.0",
    "collection_profile": "local_transcript_slice1",
    "redaction_policy": { "applied": true, "level": "standard" },
    "redaction_summary": {            // optional — 아래 callout 참조
      "total_items_redacted": 0,
      "rules_seen": [],
      "any_unredacted_sensitive": false
    },
    "generated_at": "2026-06-10T03:00:00Z",
    "next_cursor": null
  },
  "data": { ... }
}
redaction: redaction은 ingest 시점에 동작한다 — raw_event 저장 전에 rule pack v1(11규칙)으로 payload를 scan하여 마스킹된 텍스트를 저장한다(high_entropy_heuristic.v1은 flag-only, 마스킹하지 않음). 따라서 API가 반환하는 raw payload도 마스킹된 텍스트다. redaction_policy는 {applied: true, level: "standard"}로 선언되며, redaction_summary는 /v1/sessions(목록 첫 번째 = 최신 1개 세션 기준 집계로 단순화된 구현)와 /v1/sessions/:id/events(cursor window 응답)에 실린다 — /v1/events/:id/raw에는 실리지 않는다. 규칙 목록·manifest 상세는 Security Spec 05 §04 참조.

주요 DTO 계약

  • usage: assistant_events(usage_facet 행 수 = assistant 출력 event 수)와 user_turns(distinct turn_id 수 = 사용자 prompt 수)를 제공한다. per-session cache_hit_ratio scalar는 없다 — 소비자가 토큰 성분으로 계산한다. estimated_cost_usd는 공개 단가 추정이며 실제 청구가 아니다 (cost_basis = "estimate_public_pricing", models_without_pricing으로 미가격 모델 공개).
  • metrics (SessionMetrics): count만 노출 — tool_call_total, tool_failure_count, verification_total/passed/failed/unknown, context_bloat_count, tool_user_rejected/tool_policy_denied/tool_cancelled/tool_backgrounded(disposition 축), detector_firing{}. rate scalar 없음 — rate는 소비자가 count로 계산한다. verification_unknown은 측정 실패이지 검증 실패가 아니다 — pass/fail 분모에서 제외할 것.
  • verification_run: status ∈ passed|failed|unknown · status_provenance ∈ measured|estimated|unknown · status_basis ∈ exit|piped|user_rejected|policy_denied|cancelled|background · detection_basis = known_tool (older data row에는 test_keyword 값이 존재할 수 있다 — 신규 생성되지 않는다) · command_kind ∈ test_suite_js/rust/py/go/java, build, build_check, lint, format_check.
  • signal (SignalDto): signal_id, schema_version, session_id, detector(@v1 버전스탬프), subkind, summary, evidence_refs[](필수), facts{}, provenance{detector, version:"L1", rule_pack}, created_at. severity/confidence/status 같은 judgment 필드는 의도적으로 없다.

04Filtering and Pagination

session events window: GET /v1/sessions/:id/events의 no-cursor 초기 window는 raw 최신순이 아니라 렌더되는 event 기준 conversation-anchored([limit번째 최신 렌더 event, 최신 렌더 event] 범위, 사이 텔레메트리 포함)다 — 텔레메트리 버스트로 끝나는 세션의 빈-화면 방지. 디테일용 on-demand 상관 조회 파라미터 ?tool_use_id=… / ?request_id=…를 지원한다(payload의 correlation 키로 텔레메트리 반환, cursor 없는 targeted 응답). 설계 근거: implementation-notes.html#conversation-anchored-window.

05MCP Streamable HTTP Contract

서비스는 로컬 MCP server로도 동작한다. 기본 endpoint는 http://127.0.0.1:{port}/mcp이며, POST로 JSON-RPC messages를 받고 GET + SSE로 server-to-client streaming을 제공할 수 있다.

Supported JSON-RPC methods

initialize · tools/list · tools/call · resources/list · resources/templates/list · resources/read · prompts/list. capability 선언: tools: { listChanged: false }, resources: { subscribe: true, listChanged: false }, prompts: { listChanged: false }, logging: {}. 제공되는 prompt는 없다 — prompts/list는 빈 목록({ "prompts": [] })을 반환한다.

MCP resource URI scheme src/api/mcp/resources/parse.rs

whats-in-my-cc://sessions/{session_id}
whats-in-my-cc://file-lineage/{session_id}
whats-in-my-cc://otel/traces/{trace_id}

resources/list는 저장된 세션들을 whats-in-my-cc://sessions/{session_id} URI로 나열한다. 위 3개 template 외 패턴은 인식되지 않는다.

06Streaming — GET /v1/stream (SSE)

ingest writer가 event를 쓸 때마다 LiveEvent envelope을 SSE로 전달한다. WebUI의 라이브 갱신이 이 stream을 소비한다. domain data를 수정하지 않는다.

  • 재연결 backfill: Last-Event-ID 헤더 또는 ?last_event_id= query로 cursor를 전달하면 그 이후 event를 backfill(최대 10,000행) 후 live forward로 전환한다. cursor 없으면 backfill 없이 live만.
  • keepalive: --sse-keepalive-secs(기본 30) 주기 keepalive, --sse-channel-capacity(기본 512) broadcast 버퍼.
  • MCP streaming: GET /mcp는 MCP Streamable HTTP의 server-to-client SSE 채널이다. server가 발행하는 notification은 transport 수준(notifications/initialized echo 등)이며, domain 수준 stream event는 존재하지 않는다 — 라이브 갱신은 Pull API 측 GET /v1/stream(SSE)이 담당한다.

07Auth, Origin, and Local Binding

  • 기본 bind: 127.0.0.1 (--bind로 변경 시 explicit opt-in). 기본 port 7878.
  • auth 기본 = off (단일 사용자 dev). wimcc serve --auth on으로 켜면 bearer token 검증이 활성화된다.
  • auth 적용 범위 (on일 때): 모든 /v1/* GET endpoint + /mcp에 Authorization: Bearer <token> 필요. 예외(항상 열림): /otel/*·/hooks/* collectors, /v1/stream(SSE), static SPA. 토큰 비교는 constant-time(subtle).
  • token 위치: macOS ~/Library/Application Support/wimcc/token · Linux ~/.config/wimcc/token, mode 0600 (과잉 권한이면 기동 거부). CLI: --print-token, --rotate-token.
  • Host allowlist: 전 route에 host allowlist middleware가 적용된다 (DNS rebinding 방어).
  • redaction: ingest 시점에 rule pack v1(11규칙)으로 마스킹된 payload가 저장된다 — API가 반환하는 raw payload는 마스킹된 텍스트다 (§03 redaction callout, Security Spec 05 §04).

08Error Model

오류 본문은 RFC 7807 스타일의 {type, title, detail} JSON이다 (서버 오류·일부 경로는 단순 {"error": …}).

{
  "type": "about:blank",
  "title": "RESOURCE_NOT_FOUND",
  "detail": "session sess_123 not found"
}
TitleMeaningHTTP
RESOURCE_NOT_FOUNDsession / event / verification_run id 없음404
{"error":"signal not found","signal_id":…}signal id 없음 — RFC 7807이 아닌 단순 {"error": …} 형식404
INVALID_CURSORbefore/after cursor 파싱 실패400
RESOURCE_GONEretention sweep로 삭제된 resource (tombstone 기록) — "없었던 것"(404)과 구분410
(본문 없음)auth on일 때 token 누락/불일치, 또는 malformed last_event_id(plain text)401 / 400
{"error":"internal server error"}내부 오류500
