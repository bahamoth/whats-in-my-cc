02Product Definition

What's in My Claude Code는 Claude Code 실행 중 발생하는 transcript, OpenTelemetry, hook lifecycle, file/git state, verification run을 수집·정규화·연결하여 사용자가 실행 흐름과 문제 원인을 이해할 수 있도록 돕는 로컬 서비스다.

제품의 핵심 산출물은 개선 패치가 아니라 evidence-linked insight resource다. 사용자는 UI에서 causal replay, source timeline, why panel, finding, context map, verification map을 확인한다. 외부 도구는 Pull API 또는 MCP Streamable HTTP로 동일한 resource를 읽는다.

03Goals and Non-goals

Goals

  • Claude Code 실행을 통합 인과 그래프로 설명한다.
  • OTel metrics/events/traces를 1급 source layer로 다룬다.
  • 파일 변경과 검증 run의 연결을 보여준다.
  • source별 raw evidence와 normalized graph를 모두 제공한다.
  • 사용자에게 missing verification, context bloat, risky action, tool failure 등의 insight를 제공한다.
  • Pull API와 MCP Streamable HTTP로 읽기 중심 resource access를 제공한다.

Non-goals

  • Claude Code 설정, hook, command, skill, memory를 수정하지 않는다.
  • 개선 patch나 설치 스크립트를 생성하지 않는다.
  • 외부 시스템이 finding/resource에 correction이나 label을 쓰는 기능을 제공하지 않는다.
  • hidden reasoning 또는 private chain-of-thought를 복원한다고 주장하지 않는다.
  • 원격 multi-user SaaS 운영 요구사항을 MVP 범위로 두지 않는다.

06Requirement Catalog

Observation

OBS-1Transcript CaptureCore
Requirement
Claude Code transcript/JSONL에서 user message, assistant message, tool call, tool result, large output reference를 수집한다.
Acceptance
알 수 없는 필드는 raw payload에 보존하고 normalized event와 source offset을 연결한다.
OBS-2OTel Signal CaptureCore
Requirement
metrics, logs/events, traces를 모두 수집 가능한 1급 source layer로 정의한다.
Acceptance
trace/span hierarchy와 prompt/tool/session correlation key가 data model의 optional add-on이 아니라 기본 field로 존재한다.
OBS-3Hook Lifecycle CaptureCore
Requirement
session, turn, tool, permission, subagent, compaction, MCP elicitation, worktree 관련 hook event를 수집한다.
Acceptance
hook 수집 실패가 Claude Code 실행 자체를 깨지 않도록 degrade semantics를 정의한다.
OBS-4File/Git State ObservationCore
Requirement
read/write/edit, diff hunk, pre/post snapshot, branch, commit, dirty state, verification command result를 관측한다.
Acceptance
특정 diff hunk에서 prompt, tool call, verification run으로 역추적 가능해야 한다.

Graph and Insight

NOR-1Source-preserving NormalizationCore
Requirement
모든 raw source event를 ObservedEvent로 변환하되 source payload reference를 유지한다.
Acceptance
통합 graph node에서 원본 transcript, OTel span/log, hook event, file event로 jump 가능해야 한다.
⚠ 2026-06-04 (PR #33): 구현된 뷰에서 raw source로의 jump는 graph node가 아니라 ObservedEvent 단위로 이뤄진다(/v1/events/:id/raw). 요구의 의도(원본으로 jump)는 유지되되 경로가 event 기반이다. 상세: implementation-notes.html#event-first-redesign.
COR-1Deterministic CorrelationCore
Requirement
session.id, prompt.id, tool_use_id, trace_id, span_id, file_path 등 확정 key로 graph edge를 만든다.
Acceptance
동일 tool call이 transcript, OTel, hook에 중복으로 보이면 하나의 logical node로 병합한다.
COR-2Causal Edge InferenceCore
Requirement
error→repair, permission→block/allow, edit→verification 같은 관계를 confidence-scored inferred edge로 생성한다.
Acceptance
추정 edge는 deterministic edge와 구분하고 evidence, rule, limitation을 포함한다.
INS-1Evidence-linked FindingsCore
Requirement
missing verification, tool failure, context bloat, stuck loop, risky action, final-state mismatch 등 finding을 생성한다.
Acceptance
evidence_refs가 없는 finding은 저장·표시·export할 수 없다.

Serving

SRV-1Local UICore
Requirement
Integrated Causal Replay, Source Views, Why Panel, Resource Drawer를 제공한다.
Acceptance
사용자는 한 세션에서 원인 후보, 근거, 한계, raw source를 끊기지 않고 탐색할 수 있다.
SRV-2Pull APICore
Requirement
외부 도구가 session, graph, finding, context map, file lineage, export bundle manifest를 GET 중심 API로 조회한다.
Acceptance
API는 domain schema를 반환하고 UI 렌더링 구조에 의존하지 않는다.
SRV-3MCP Streamable HTTPCore
Requirement
로컬 MCP endpoint를 통해 동일 resource와 read-only tools를 제공한다.
Acceptance
endpoint는 localhost binding, Origin validation, local auth token을 기본 보안 요구사항으로 둔다.
