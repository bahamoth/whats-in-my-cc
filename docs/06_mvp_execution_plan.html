MVP Execution Plan

OTel-first 단일 세션 분석 MVP를 구현하기 위한 범위, 마일스톤, acceptance criteria, test matrix를 정의한다.

MVPAcceptanceOTel in M1

01MVP Strategy

MVP의 목적은 “한 세션을 정확히 이해하고 설명하는 것”이다. cross-session advanced analytics보다 단일 세션의 high-fidelity replay, OTel-linked graph, evidence-backed finding을 먼저 완성한다.

MVP 기준: transcript + OTel + hook를 모두 초기 schema에 포함한다. Slice-10a (2026-05-22): 별도의 file/git collector는 제거됐다 — file lineage는 transcript toolUseResult.structuredPatch에서 derived. 일부 collector가 mock/adapter 수준이어도 data model과 graph contract는 OTel-first로 고정한다.

04Milestone Details

M0 · Spec freeze

문서 세트 승인, naming, collection profile, endpoint surface 확정.

M1 · Source ingestion

transcript parser, OTel receiver/adapter, hook receiver, file/git observer를 통해 raw events 저장.

M2 · Normalized model

ObservedEvent, telemetry facet, source_refs, redaction manifest, schema registry 구현.

M3 · Graph builder

node merge, deterministic edges, basic causal inference, lineage mapping.

M4 · UI replay

Session dashboard, integrated causal replay, source views, why panel, resource drawer.

M5 · Insight engine

missing verification, tool failure, risky action, context bloat, final-state mismatch finding 생성.

M6 · Pull API and MCP

GET endpoints, MCP resources, read-only tools, streaming status events.

M7 · Security hardening

Origin validation, localhost binding, token, redaction/export preview, retention cleanup.

09Definition of Done

Functional

사용자가 한 세션을 열고 causal replay, source views, why panel, findings를 확인할 수 있다.

Data

OTel-linked ObservedEvent와 graph schema가 안정적으로 export/query된다.

Security

localhost bind, token, Origin validation, redaction manifest가 기본으로 동작한다.
