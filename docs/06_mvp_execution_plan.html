01MVP Strategy

MVP의 목적은 “한 세션을 정확히 이해하고 설명하는 것”이다. cross-session advanced analytics보다 단일 세션의 high-fidelity replay, OTel-linked graph, evidence-backed finding을 먼저 완성한다. 완료 당시 계획 · 이후 변경: graph는 2026-06-07 삭제(→ ObservedEvent + correlation 키 event-first 렌더), Finding은 Signal로 대체 — evidence-linked 원칙 자체는 Signal의 evidence_refs 필수로 유지

MVP 기준: transcript + OTel + hook를 모두 초기 schema에 포함한다. Slice-10a (2026-05-22): 별도의 file/git collector는 제거됐다 — file lineage는 transcript toolUseResult.structuredPatch에서 derived. 일부 collector가 mock/adapter 수준이어도 data model과 graph contract는 OTel-first로 고정한다. graph contract는 이후 삭제 — OTel-first 고정은 ObservedEvent correlation 키(trace_id/span_id 1급)로 유지

04Milestone Details

아래 마일스톤은 전부 완료됐다(M0~M7 closed, 2026-05-27 EXIT). 원문은 계획 당시 서술 그대로 보존하고, 이후 구조가 바뀐 항목에만 주석을 단다.

M0 · Spec freeze 완료

문서 세트 승인, naming, collection profile, endpoint surface 확정.

M1 · Source ingestion 완료

transcript parser, OTel receiver/adapter, hook receiver, file/git observer를 통해 raw events 저장. 당시 계획 · file/git observer는 slice-10a에서 제거 — file lineage는 transcript structuredPatch에서 derived

M2 · Normalized model 완료

ObservedEvent, telemetry facet, source_refs, redaction manifest, schema registry 구현. redaction manifest 구현됨 — slice-18 ingest gate(rule_pack@v1), raw_event.redaction_manifest + meta.redaction_summary

M3 · Graph builder 완료

node merge, deterministic edges, basic causal inference, lineage mapping. 당시 계획 · 산출물은 2026-06-07 전량 삭제 — event-first(ObservedEvent + correlation 키)로 대체, lineage는 diff_hunk 사이드테이블로 유지

M4 · UI replay 완료

Session dashboard, integrated causal replay, source views, why panel, resource drawer. 당시 계획 · 2026-06-04 event-first 재설계로 대체 — 현행: 대화 스트림 + per-event 디테일 패널 + Raw 탭 + insight strip + 분석 패널

M5 · Insight engine 완료

missing verification, tool failure, risky action, context bloat, final-state mismatch finding 생성. 당시 계획 · Finding→Signal 대체 — 현행 detector 5종(tool_failure, risky_action, context_bloat, final_state_mismatch, re_read), 전부 deterministic L1(LLM judge는 2026-06-06 삭제)

M6 · Pull API and MCP 완료

GET endpoints, MCP resources, read-only tools, streaming status events. graph·findings 계열 endpoint/도구는 이후 삭제 — 현행 MCP 도구 4종: search_sessions, get_file_lineage, get_otel_trace, list_detectors

M7 · Security hardening 완료

Origin validation, localhost binding, token, redaction/export preview, retention cleanup. 현행: auth 기본 off(단일 사용자 dev), retention 기본 none, ingest redaction 구현 — export preview는 미구현

09Definition of Done

DoD는 2026-05-27 MVP EXIT으로 충족 처리됐다. 아래 원문 중 graph·finding·redaction 서술은 당시 기준 — 주석 참조.

Functional

사용자가 한 세션을 열고 causal replay, source views, why panel, findings를 확인할 수 있다. 현행: event-first replay(대화 스트림·디테일 패널·Raw 탭) + Signal·insight strip·분석 패널

Data

OTel-linked ObservedEvent와 graph schema가 안정적으로 export/query된다. graph schema는 이후 삭제 — ObservedEvent + side-tables(usage_facet·diff_hunk·verification_run) + signal로 대체

Security

localhost bind, token, Origin validation, redaction manifest가 기본으로 동작한다. 현행: localhost bind 기본, auth 기본 off, ingest redaction manifest 구현

10피드백 필요 사항

당시의 열린 질문 — 전부 해소됨. 결론을 주석으로 표시.

  1. MVP에서 cross-session pattern을 완전히 제외할지, read-only aggregate 정도는 포함할지 결정 필요. 해소: read-only aggregate만 포함 — /v1/usage/baseline(세션 횡단 p25/median/p75)
  2. 초기 UI를 dashboard-first로 구현할지, replay-first로 구현할지 결정 필요. 해소: replay-first — /sessions/:id event-first replay가 중심, 세션 목록은 진입점
  3. OTel collector를 테스트하기 위한 fixture format을 실제 OTLP export로 만들지, normalized fixture로 시작할지 결정 필요. 해소: real payload 동결(tests/fixtures/**/real/) — Real-data anchoring 원칙으로 승격

11Post-MVP 후속 트랙 (2026-06-10 추가)

MVP EXIT(2026-05-27) 이후의 주요 구조 변화 요약. 이 계획서의 범위 밖에서 수행된 별도 트랙이며, 위 §01~§10의 graph·judge·finding 서술을 대체한 현재 구조다. 상세·근거는 docs/implementation-notes.html(#judge-removal·#graph-removal·#event-first-redesign 등).

2026-06-04 · event-first 뷰 재설계 (PR #33)

메세지·디테일·raw 뷰를 graph node/facet 기반에서 ObservedEvent + correlation 키 직접 렌더로 전환. M4의 why panel·causal replay 서술을 대체.

2026-06-06 · LLM judge 서브시스템 삭제

기본 비활성으로 휴면 상태였고, 비결정·비로컬 LLM이 deterministic·local-first 철학과 충돌. --judge* serve 플래그 3종 제거, 모든 extractor가 deterministic L1로 직접 승격 (migration 0018).

2026-06-07 · graph 레이어 전량 삭제 (refactor/drop-judge-graph)

graph node/edge는 어떤 뷰의 backing도, insight의 근거도 아니었음이 확인됨. graph_node/graph_edge 테이블·src/graph/·edge_inference·/graph Pull API·MCP get_session_graph/explain_node 제거 (migration 0019). ingest는 insight 파이프라인을 직접 호출.

Finding → Signal 전환

Finding/RootCauseHypothesis/QualitySummary 스키마와 /v1/findings*·tool-failures API·MCP search_findings를 삭제하고 Signal로 대체 (migration 0021): detector(@v1 버전스탬프)·subkind·facts·evidence_refs 필수·provenance{detector, version "L1", rule_pack}. AC-4의 evidence-linked 가드레일은 그대로 승계. detector 5종: tool_failure·risky_action·context_bloat·final_state_mismatch·re_read.

F1 / F2 / F5 · 지표·검증 정합성 트랙

F1: window-고정 rate scalar(verification_pass_rate·tool_failure_rate·cache_hit_ratio) 삭제 — /metrics·/usage는 합성 가능한 count만 노출, rate는 소비자가 계산(cache_hit_ratio 분포는 /v1/usage/baseline에만 존재). F2: Tier-2 test_keyword 검출 폐기 — prose가 phantom verification run을 만들던 경로 차단, detection_basis는 known_tool만 신규 생성(test_keyword는 legacy row 전용). F5: verification outcome success-detection — 높은 unknown 비율의 근본 원인 해소, outcome resolution 체인(OTLP→hook exit_code→transcript "Exit code N"→<tool_use_error>→Tier-4 estimated 텍스트 패턴) 정비, status_provenance(measured/estimated/unknown) 도입 (migration 0022).

2026-06-10 · deterministic disposition 분류

tool_result 하니스 마커 prefix로 user_rejected·policy_denied·cancelled·backgrounded를 결정론적으로 분류 — SessionMetrics에 tool_user_rejected 등 카운트 추가, disposition이 잡히면 Tier-4 estimated 패턴 미적용.

현행 파이프라인(graph 없음): transcript live tail + ingest backfill + OTel/hook collectors → raw_event(원본 보존) → ObservedEvent → side-tables(usage_facet·diff_hunk·verification_run) → insight 파이프라인 직접 호출 → signal → 조회 시 on-demand SessionMetrics. SSE /v1/stream이 WebUI 라이브 갱신. migrations 최신 0022.
