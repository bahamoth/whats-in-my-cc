Product Design Spec

사용자가 Claude Code 실행을 이해하기 위한 화면, 흐름, interaction, evidence UX를 정의한다.

UXevent-first replaysignal cards

01Product Intent

이 제품의 UX 목표는 “Claude Code가 실제로 무엇을 했고, 왜 그 결과가 나왔는가?”를 사용자가 눈으로 따라갈 수 있게 만드는 것이다. 중심 경험은 chat transcript가 아니라 execution replay다.

UX 원칙: 모든 설명은 source evidence로 역추적 가능해야 한다. 사용자가 대화 스트림의 어떤 ObservedEvent를 선택하더라도 raw transcript, OTel span/log, hook event 중 최소 하나의 raw source로 돌아갈 수 있어야 한다(Raw 탭 / /v1/events/:event_id/raw).

화면은 2개다: /sessions(최근 세션 목록)와 /sessions/:id(event-first replay). insight 표면은 Signal 카드와 분석 패널이다.

02Primary Personas

Owner / Operator

로컬에서 본인 Claude Code 세션을 분석한다. 비용, 실패, 검증 누락, context 낭비를 확인한다.

Developer Debugger

특정 코드 변경이 어떤 tool call과 verification 결과로 이어졌는지 확인한다.

External Reader

Pull API나 MCP로 resource를 읽어 별도 개선·분석 작업에 활용한다. 쓰기 권한은 없다.

03Information Architecture

04Sessions 목록 + Insight Strip

landing page는 /sessions — 최근 세션 목록(최신순)이다. 세션을 클릭하면 /sessions/:id replay로 들어가고, replay 상단의 insight strip이 세션 상태의 executive summary 역할을 한다. 별도 dashboard 화면은 없다.

Insight strip 카드 (5종)

컨텍스트 효율

context_bloat 등 컨텍스트 낭비 신호 기반.

토큰

usage facet 기반 토큰 4종 + billed_tokens, by_model.

검증

verification run의 passed/failed/unknown count. 표시 rate는 count에서 클라이언트가 계산(F1 — 서버는 rate scalar를 내보내지 않음).

도구 실패 · 비용

tool_failure_count와 estimated_cost_usd(공개 단가 기반 추정).

insight strip에는 provenance 배지가 붙는다 — 값이 measured인지 estimated인지(예: 비용은 항상 추정, verification status는 status_provenance measured/estimated/unknown)를 구분해 보여준다.

05Event-first Replay (/sessions/:id)

replay 화면은 단일 대화 스트림이다. ObservedEvent(user_message · assistant_message · thinking · tool_call · tool_result · hook_event · otel_span 등)가 시간순으로 흐르고, 카드/활동(beat)을 클릭하면 그 event가 선택된다. per-event 디테일 패널은 tool_use_id / request_id / turn_id / message_id correlation 키로 correlate된 텔레메트리 event에서 채워진다.

화면 구성: 대화 스트림 + per-event 디테일 패널 + Raw 탭 + insight strip(§04) + 분석 패널(§07) + untagged-Bash 패널(태깅 루프). 라이브 갱신은 SSE /v1/stream.

lane·causal edge 시각화는 제공하지 않는다 — 스트림은 단일 시간축이다.

06Raw Source Access

source별 독립 뷰(Transcript/OTel/Hook/Git 전용 화면)는 제공하지 않는다. source-preserving 원칙이 같은 목적을 충족한다: 모든 source payload는 raw_event에 원본 그대로 보존되고, replay의 Raw 탭과 read-only API로 접근한다.

Transcript source

transcript JSONL 원본 — 선택 event의 Raw 탭, /v1/events/:event_id/raw.

OTel source

OTLP traces/metrics/logs 원본 — otel_span·metric_sample·log_record event의 Raw 탭, MCP get_otel_trace.

Hook source

hook stdin 원본 — hook_event(subkind: pre_tool_use/post_tool_use 등)의 Raw 탭.

File/Verification side-tables

/v1/sessions/:id/diff-hunks · /v1/sessions/:id/verification-runs · MCP get_file_lineage.

중요: 해석(normalized event·signal)이 틀렸는지, source 수집이 누락됐는지 분리 판단할 수 있도록 raw payload는 가공 없이 보존된다. source 수집 상태 자체는 /v1/health/sources로 확인한다.

07Signal 카드 & 분석 패널

insight 표면은 Signal 카드와 분석 패널 둘이다. 모든 signal은 deterministic detector가 만들고 evidence event로 역추적된다.

Signal 카드

  1. summary: 무슨 일이 일어났는가
  2. facts(JSON): 결정적으로 관측된 사실
  3. evidence_refs: 근거 event — 필수, 없으면 signal을 만들지 않는다
  4. detector: 어떤 규칙이 발화했는가 (@v1 버전스탬프)
  5. provenance: {detector, version:"L1", rule_pack} — 모든 detector는 deterministic L1 (LLM 기반 판정은 없다)

Detector 5종: tool_failure · risky_action · context_bloat · final_state_mismatch · re_read. manifest는 /v1/detectors + MCP list_detectors.

분석 패널 + Display constraints

세션 지표(SessionMetrics — 온디맨드 계산, 저장 없음: tool_call_total, tool_failure_count, verification_total/passed/failed/unknown, context_bloat_count, disposition별 count)와 detector 분포(detector_firing)를 표시한다.

  • evidence 없는 claim 표시 금지 (signal은 evidence_refs 필수)
  • hidden reasoning 기반 설명 금지
  • measured/estimated/unknown provenance를 구분 표시
  • rate scalar는 서버가 내보내지 않는다 — count에서 소비자가 계산(F1)

08Resource Access (Pull API / MCP)

resource 전용 UI 화면은 없다. 외부 접근은 read-only Pull API({meta:{schema_version, collection_profile, generated_at,…}, data:…} 래핑)와 MCP Streamable HTTP(/mcp, 도구 4종)로 한다. 인증 기본값은 --auth off(단일 사용자 dev), 바인딩 기본값은 127.0.0.1.

09Empty / Error States

Missing OTel

OTel source가 없으면 outcome resolution이 다음 tier로 fallback한다(①OTLP tool_result log → ②hook post_tool_use exit_code → ③transcript "Exit code N" / <tool_use_error> → ④unknown). 결과의 status_provenance가 measured/estimated/unknown으로 구분 표시되고, source 상태는 /v1/health/sources로 확인한다.

Uncorrelated event

correlation 키(tool_use_id/request_id/turn_id/message_id)가 없는 event도 스트림에는 시간순으로 표시된다. 디테일 패널의 correlate된 텔레메트리 영역만 비게 된다.

Sensitive content

ingest 시점 redaction gate(rule_pack@v1, slice-18)가 raw payload 저장 전에 secret 패턴을 마스킹하고 redaction_manifest를 남긴다. 단 high-entropy 문자열은 flag-only이고 export-side review·경로 redaction은 제공하지 않는다 — DB와 127.0.0.1 노출분은 여전히 민감 데이터로 취급할 것.
