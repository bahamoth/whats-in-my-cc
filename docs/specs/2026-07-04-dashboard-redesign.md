# 대시보드 전면 개편 — 확정 스펙 (2026-07-04)

사용자 승인 목업: `docs/mockups/dash-full-mockup.html`(대시보드), `docs/mockups/dash-verification-mockup.html`(검증).
목업은 자기완결 HTML + 로컬 `vendor-echarts.min.js` — 브라우저로 직접 열어 인터랙션 확인 가능.
탐색 이력(기각안 포함): `dash-redesign-directions.html`, `dash-timeseries-ideas.html`.

## 0. 확정 원칙

1. **위계**: 결정론 지표의 문자 요약(색·굵기·크기로 delta 전달)이 맨 위 → 그 아래 시각화.
2. **인사이트 우선**: 각 모듈은 "답할 질문"이 먼저고 형태는 질문이 결정한다. 바/라인 관성 금지.
3. **판정 문장 금지**: 숫자·delta·관측 사실만. "좋아졌다/나쁘다" 류 단어는 어떤 경로로도 생성하지 않는다.
   섹션 제목은 질문형("~인가/~났나") 금지 — 서술형 라벨.
4. **모델명은 전체 표시명**("Fable 5", "Opus 4.8"). 약칭(F5·O4.8·이니셜) UI 표기 금지.
   공간 부족은 레이아웃으로 해결.
5. **페이지 전체 활용**: max-width 제약 없음, 모듈당 250~400px. 좁은 영역 압축으로 인한 열화 금지.
6. **차트 도구 기준**: 좌표계(축·스케일·줌·크로스헤어)가 있으면 라이브러리, 텍스트 중심
   배치 컴포넌트(카드 레인·커버리지 바)는 DOM/CSS.
7. **표본 정직성**: 코호트 비교는 전/후 n 병기, 표본 1~2건이면 delta 강조 해제 + "표본 부족" 표기.
   0과 미측정을 구분한다(미측정 = `—`, 셀 미표시).

## 1. 대시보드 페이지 구성 (위→아래)

필터 컨텍스트(프로젝트·기간 창)는 페이지 전역 공유. 모든 시간축 차트는 코호트 전환
마커(점선+라벨)가 관통하고 crosshair 동기.

| # | 모듈 | 답하는 질문 | 형태 | 비고 |
|---|------|------------|------|------|
| 1 | 문자 헤드라인 | 지난 창보다 달라졌나 | 큰 타이포 stat 5개 + delta 칩 + "관측된 변화" 줄 | delta는 이전 동일 창 대비. 변화 줄 = 코호트 diff·신호 최다 세션 (결정론 템플릿) |
| 2 | 검증 결과 — 일별 | 검증이 언제 통과/실패/판정불가였나 | 일별 스택바(통과·실패·판정불가) | 캡션에 "가드 0 세션 n개" |
| 3 | 일별 비용 · 신호 | 돈과 문제가 언제 몰렸나 | 일별 비용 바 + **막대 색 = 그날 신호 수(연속 그라데이션 초록→앰버→적)** + 그라데이션 범례 + dataZoom | 툴팁에 그날 세션 목록 |
| 4 | 코호트 비교 | 최신 경계 전후 무엇이 변했나 | 지표 4종(단가·통과율·신호/세션·적중) 슬로프 카드 | §2 규칙 |
| 5 | 세션 타임라인 | 그날의 집계를 만든 세션은 누구인가 + 작업 리듬 | 실제 시간축 위 세션 카드 레인(겹침은 레인 스택) | 카드: 슬러그·모델 전체명·$비용·n신호·통과%·날짜·events. 신호 밀도 > 중앙값×2 → 신호 숫자 앰버. 클릭→리플레이 |
| 6 | 세션 분포 | 어느 세션이 벗어나 있나 | 스캐터: x 과금 토큰(log)·y 신호/100events·크기 비용·색 주 모델·중앙값 점선·이상점 라벨 | 클릭→리플레이 |

정확한 값 훑기·정렬은 대시보드가 하지 않는다(→ §4 /sessions).

## 2. 코호트 비교 — 결정론 규칙

1. 경계 검출 SSOT = `lib/seriesView.cohortSegments/cohortBoundaries`(기존, vitest 잠금).
   fingerprint(모델 집합·CC 버전)가 비어있지 않은 직전 값과 달라지는 지점.
2. 라벨 자동 파생: `added = after−before`, `removed = before−after` →
   `"{전체 표시명} 유입"` / `"… 이탈"` / 둘 다면 `"A → B"`. 미래 모델도 자동.
3. 비교 대상: 기본 = 창 안의 **가장 최근 경계**, 전/후 = 경계의 **인접 세그먼트**.
   모듈 3의 경계 마커 클릭으로 다른 경계 선택.
4. 제목 = i18n 템플릿 `"코호트 비교 — {label} 전후"` — 모든 토큰이 고정 문자열 또는
   테스트된 순수 함수 산출값. 같은 경계에서 모델·CC 동시 변경 시 각주로 명시(효과 분리 불가).

## 3. 검증 화면 (대시보드 "검증" 탭 — 제안)

같은 필터 컨텍스트에서 탭으로 전환. 모듈과 결정론 파생:

| 모듈 | 인사이트 | 파생 |
|------|---------|------|
| 문자 헤드라인 5칸 | 가드 총수 / 측정률(+판정불가 원인 분해) / 통과(측정분) / **실패 방치** / **변경 커버리지** | 파이프 마스킹 = `status_basis`; 실패 방치 = 세션 내 같은 kind의 시간순 outcome 시퀀스가 실패로 종료; 커버리지 = `covered_diff_hunk_ids`/전체 diff hunk |
| 종류별 결과 구성 | 어떤 kind가 측정이 안 되나 | kind × outcome 100% 가로 스택 + 건수 |
| 가드의 행방 (Sankey) | 실패가 복구됐나 방치됐나 | 가드→측정/판정불가→통과/실패→복구/방치, 판정불가→원인 |
| 가드 실행 리듬 | TDD 리듬 vs 끝몰림 vs 마스킹 | 세션 진행률(이벤트 %) 위 outcome 점 스트립, 신호 상위 세션 |
| 변경 커버리지 | 검증 안 거친 변경 | 세션별 커버/미커버 hunk 바(hunk 상위 세션) |

## 5. 기술 결정

- **차트 라이브러리**: 목업 수준의 인터랙션(dataZoom, Sankey, 스캐터 labelLayout, 리치 툴팁,
  visual 연출)은 Recharts로 재현이 어렵다. **대시보드·검증 화면은 ECharts 도입**
  (tree-shaken import로 번들 최소화: bar/scatter/sankey + tooltip/dataZoom/markLine만).
  기존 Recharts 화면은 건드리지 않는다. 구현 중 번들 영향(±KB) 측정해 notes에 기록.
- 색 토큰: 앱 quiet-editorial 팔레트 재사용. 통과 `--ok`, 실패 `--dng`, 판정불가 회
  (#4a5162), 신호 히트 램프 `#41c285→#c9c04a→#f0a03c→#ef6047`.
- 데이터: 기존 `/v1/metrics` 시리즈 + 일별 집계는 프론트 파생. 검증 탭은
  verification-runs 집계 API 필요 여부 검토(세션별 조회 N+1 회피) — 구현 시 결정.
- 백엔드 후보: 이전-창 delta·실패 방치·커버리지 집계가 프론트 N+1이면
  `/v1/metrics` 확장(TDD).
