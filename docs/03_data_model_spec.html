Data Model Spec

RawEvent, ObservedEvent(telemetry facet 포함), file lineage(DiffHunk), VerificationRun, Signal, SessionMetrics/usage schema를 정의한다. graph(node/edge) 스키마는 2026-06-07 삭제됐다 — 뷰와 insight는 ObservedEvent + correlation 키로 직접 동작한다(event-first).

SchemasEvent-firstEvidence

01Data Model Principles

  1. OTel-first: trace_id/span_id/metric/log reference는 나중에 붙이는 optional metadata가 아니라 ObservedEvent의 1급 correlation 컬럼·telemetry facet의 핵심 field다.
  2. Source-preserving: normalized object는 항상 raw source reference(raw_event_id)를 갖는다. unknown field는 payload JSON에 보존된다.
  3. Evidence-linked: Signal은 비어 있지 않은 evidence_refs 없이 존재할 수 없다 (AC-4).
  4. No annotation model: 사용자/외부 서비스가 signal에 correction, label, status를 쓰는 domain object는 정의하지 않는다.
  5. Schema versioning: 모든 top-level object는 schema_version과 provenance를 가진다.
  6. Deterministic L1: 모든 detector는 결정론 규칙이다. severity/confidence 같은 판단(judgment) 필드는 저장하지 않는다 — facts만 저장한다. (LLM judge 서브시스템은 2026-06-06 삭제.)
  7. 합성 가능한 count만 (F1): window-고정 rate scalar는 저장·반환하지 않는다. rate = count / window이고 window는 분석마다 다르므로 소비자가 계산한다.

02Entity Relationship Map

2026-06-07 graph 삭제 후의 현행 엔티티. GraphNode/GraphEdge·Finding·FeedbackResource/ExportBundle은 더 이상 존재하지 않는다. SessionMetrics는 저장 테이블이 아니라 조회 시 on-demand 집계다(점선).

transcript live tail + ingest backfill + OTel/hook collector → raw_event(원본 보존) → observed_event → side-table(usage_facet · diff_hunk · verification_run) → ingest가 insight 파이프라인(detector 5종)을 직접 호출 → signal → 조회 시 on-demand SessionMetrics. graph rebuild 단계는 없다.

05Graph — 삭제됨 (2026-06-07)

GraphNode/GraphEdge 스키마는 완전히 삭제됐다 (2026-06-07, refactor/drop-judge-graph, migration 0019에서 graph_node/graph_edge 테이블 drop). src/graph/·edge_inference·/v1/sessions/:id/graph Pull API·MCP get_session_graph/explain_node도 함께 제거됐다. 이 문서의 이전 판이 정의했던 node/edge JSON과 edge type 표는 git history에서만 유효하다.

대체: correlation 키 기반 event-first

graph는 어떤 뷰의 backing도, signal의 근거도 아니었다 — 메세지·디테일·raw 뷰는 이미 ObservedEvent + correlation 키로 직접 그렸고, extractor는 이벤트만 사용했다. 따라서 별도 graph 레이어 없이:

  • tool_call ↔ tool_result 페어링: tool_use_id 컬럼 (partial index idx_obs_tool_use_id).
  • API 요청 단위 묶음: request_id 컬럼 (0020에서 idx_obs_request_id 추가).
  • 턴/메세지 묶음: turn_id / message_id 컬럼.
  • transcript 연쇄: event_uuid / parent_uuid.
  • OTel 상관: trace_id / span_id / parent_span_id 컬럼.

ingest는 graph rebuild 대신 insight 파이프라인(detector)을 직접 호출한다. 근거·상세: implementation-notes.html#graph-removal, #event-first-redesign.

06ContextArtifact — 폐기

구현되지 않음 / 계획 폐기: 파생 객체 ContextArtifact는 저장 모델로 구현되지 않았다. context_bloat detector는 별도 artifact 객체 없이 ObservedEvent에서 직접 결정론 규칙으로 signal을 만든다. 마찬가지로 파생 Episode 객체와 phase enum(intake/exploration/… )도 제거됐다(migration 0017, implementation-notes #episode-removal) — 분류는 파생 episode가 아니라 개별 이벤트에 속한다.

07File Lineage and VerificationRun

Slice-10a — transcript-only file lineage: DiffHunk rows are produced from the transcript toolUseResult.structuredPatch of Edit tool_result lines. Write tool_results carry structuredPatch=[] by design and produce zero rows. No filesystem watcher, no git poller, no commit-SHA-as-verification-marker. The structuredPatch shape is locked by a real-fixture invariant test (see implementation-notes slice-10a).

VerificationRun outcome resolution 체인

  1. OTLP tool_result log (success 신호) — measured.
  2. hook post_tool_use의 exit_code — measured.
  3. transcript "Exit code N" 라인 — measured. ③b <tool_use_error> 래퍼 → Failed(measured) — 단 Cancelled disposition은 예외.
  4. Unknown. 단, test/build/lint/format kind에 한해 Tier-4(estimated) 텍스트 규칙 적용 — looks_like_failure("error[", "FAILED" 등) 우선, 그다음 looks_like_success("test result: ok" 등 결정론 성공 요약, F5). disposition 마커가 잡힌 result에는 Tier-4를 적용하지 않는다 (content가 실제 출력이 아님 — real fixture disposition_v01.jsonl).

status_basis 의미: exit = exit code 관측 경로, piped = non-pager로 파이프되어 exit code가 가려짐(status는 unknown으로 강제), 나머지 4종은 disposition 분류(2026-06-10) — tool_result의 하니스 마커 prefix로 user_rejected(사용자 거부) / policy_denied(PreToolUse hook 차단) / cancelled(병렬 호출 취소) / background(백그라운드 전환)를 기록해 측정 불가 사유를 구분한다. tool_result의 is_error는 pass/fail 판정에 사용하지 않는다.

08Signal

Finding → Signal 전환 (migration 0021): Finding/RootCauseHypothesis/QualitySummary 스키마는 폐기됐고 finding 테이블은 drop됐다. severity/confidence/claim 같은 판단(judgment) 필드는 저장하지 않는다 — Signal은 결정론 detector가 관측한 사실(facts)만 담는다. /v1/findings*·MCP search_findings도 함께 삭제됐다.
{
  "signal_id": "sig_…",            // sha256(detector ‖ session_id ‖ sorted evidence_refs)[..12]
                                   // → 재실행 idempotent (INSERT OR REPLACE)
  "schema_version": "signal.v1",
  "session_id": "sess_…",
  "detector": "tool_failure",
  "subkind": null,                 // 선택적 사실 분류 (해석 아님)
  "summary": "factual summary — 판단 어휘 없음",
  "evidence_refs": ["01J…"],       // observed_event event_id 배열 — 비어 있을 수 없다 (AC-4)
  "facts": { },                    // detector별 사실 projection — severity/confidence 없음
  "provenance": { "detector": "tool_failure@v1", "version": "L1", "rule_pack": null },
  "created_at": "…"
}

provenance.version은 항상 "L1"(deterministic — judge 레이어 없음). rule_pack은 코드 기본 detector면 null, TOML rule pack 로드 시 그 id. 외부에서 signal에 쓰는 API는 없다 (no annotation model).

09SessionMetrics & Usage

SessionMetrics — on-demand (저장 테이블 없음)

GET /v1/sessions/:id/metrics 호출 시 side-table에서 매번 재계산한다. F1: 합성 가능한 count만 — verification_pass_rate/tool_failure_rate/cache_hit_ratio 같은 window-고정 rate scalar는 삭제됐고, rate는 소비자가 자기 window로 계산한다. severity/판단/threshold 플래그 없음.

{
  "session_id": "sess_…",
  "tool_call_total": 124,
  "tool_failure_count": 3,          // tool_failure detector signal 수
  "verification_total": 9,
  "verification_passed": 7,
  "verification_failed": 1,
  "verification_unknown": 1,        // 측정 실패 — 실패가 아니다. pass/fail 분모에 넣지 말 것
  "context_bloat_count": 2,         // context_bloat detector signal 수
  "tool_user_rejected": 0,          // disposition 분류 (2026-06-10, 하니스 마커 prefix)
  "tool_policy_denied": 1,
  "tool_cancelled": 0,
  "tool_backgrounded": 2,
  "detector_firing": { "tool_failure": 3, "re_read": 1 }   // detector → signal 수
}

disposition count 4종은 실패도 unknown도 아닌 별도 축 — 실행되지 않았거나(거부/차단/취소) content가 실제 출력이 아닌(백그라운드) 호출의 결정론 분류다.

Usage — /v1/sessions/:id/usage

side-table usage_facet(assistant 출력 이벤트당 1행: model + 토큰 4종)에서 집계.

  • F1 rename: turns → assistant_events(usage_facet 행 수). user_turns 추가 — 세션의 distinct turn_id 수(= 사용자 프롬프트 수).
  • 토큰 4종: input_tokens · cache_creation_input_tokens · cache_read_input_tokens · output_tokens.
  • billed_tokens = input + cache_creation + output (cache_read는 비과금).
  • estimated_cost_usd: 공개 단가 추정 — 실제 청구가 아니다. cost_basis="estimate_public_pricing" + pricing_version + models_without_pricing(가격 미상 모델은 합계에서 제외, UI에 공시).
  • by_model: 모델별 assistant_events·토큰·추정 비용·priced 플래그. user_turns는 세션 레벨이라 per-model 없음.
  • F1: per-session cache_hit_ratio scalar 삭제 — 토큰 구성요소에서 소비자가 계산.

Usage baseline — /v1/usage/baseline

usage_facet가 있는 모든 세션 횡단 quantile(p25/median/p75): cache_hit_ratio · billed_tokens · assistant_events · output_tokens + session_count. cache_hit_ratio 분포는 baseline에만 존재한다 — 세션 횡단 quantile 분포는 유효한 비교이고, per-session scalar와 달리 F1에 저촉되지 않는다.

10FeedbackResource and ExportBundle — 미구현

구현되지 않음: FeedbackResource와 ExportBundle 스키마, 그리고 POST /v1/export-bundles는 구현되지 않았다(routes에 없음). 이전 판의 JSON 정의는 graph node id를 evidence로 참조하는 등 삭제된 모델에 묶여 있어 그대로는 유효하지 않다. 외부 소비는 현행 read-only Pull API(/v1/sessions/:id/signals, /v1/signals/:id 등)와 MCP 도구 4종으로 이뤄진다. export bundle을 되살린다면 evidence 참조는 event_id/raw_event_id 기반으로 재설계해야 한다.

12Schema Migration Policy

  • Minor schema changes must preserve existing fields or provide derived compatibility view.
  • Parser version changes must be recorded on every ObservedEvent.
  • OTel schema drift must not break raw event preservation; unknown telemetry fields는 facet의 attributes JSON에 보존된다.
  • 현행 head는 0022 — 0017 episode drop, 0018 judge drop, 0019 graph drop, 0020 request_id 인덱스, 0021 signal 테이블 + finding drop, 0022 verification_run status_provenance.
  • payload 필드(tool_call.tool_name, assistant_message.model 등)는 JSON BLOB이라 schema migration 없이 추가된다 — 기존 이벤트에 채우려면 재ingest 필요.

13피드백 필요 사항

  1. FeedbackResource 이름 결정 — 해소: FeedbackResource/ExportBundle 자체가 미구현으로 남았고, 외부 소비는 Signal 중심 Pull API/MCP로 정리됐다.
  2. confidence score 표현 방식 — 해소: confidence/severity는 판단 필드로서 모델에서 제거됐다(Signal은 facts만 저장).
  3. raw payload hash 기준 — 현행 구현(hook collector 경로 실측)은 redaction 전 canonical payload 기준으로 sha256을 계산한다. 다른 source 경로 전반의 기준 통일 여부는 검토 항목.
