Data Model Spec

RawEvent, ObservedEvent(telemetry facet 포함), file lineage(DiffHunk), VerificationRun, Signal, SessionMetrics/usage, SessionFingerprint schema를 정의한다. 뷰와 insight는 ObservedEvent + correlation 키로 직접 동작한다(event-first).

SchemasEvent-firstEvidence

01Data Model Principles

  1. OTel-first: trace_id/span_id/metric/log reference는 나중에 붙이는 optional metadata가 아니라 ObservedEvent의 1급 correlation 컬럼·telemetry facet의 핵심 field다.
  2. Source-preserving: normalized object는 항상 raw source reference(raw_event_id)를 갖는다. unknown field는 payload JSON에 보존된다.
  3. Evidence-linked: 모든 detector는 비어 있지 않은 evidence_refs를 넣도록 detector별 테스트로 잠겨 있다 (AC-4). DB CHECK 제약이나 runtime guard는 아니다 — 컬럼은 NOT NULL TEXT(JSON 배열)일 뿐이다.
  4. No annotation model: 사용자/외부 서비스가 signal에 correction, label, status를 쓰는 domain object는 정의하지 않는다.
  5. Schema versioning: 모든 top-level object는 schema_version과 provenance를 가진다.
  6. Deterministic L1: 모든 detector는 결정론 규칙이다. severity/confidence 같은 판단(judgment) 필드는 저장하지 않는다 — facts만 저장한다.
  7. 합성 가능한 count만: window-고정 rate scalar는 저장·반환하지 않는다. rate = count / window이고 window는 분석마다 다르므로 소비자가 계산한다.

Non-features: export bundle은 제공하지 않는다.

02Entity Relationship Map

SessionMetrics는 저장 테이블이 아니라 조회 시 on-demand 집계다(점선). 이 맵은 분석 데이터 모델 범위만 다룬다 — 운영 테이블(ingest_run · audit · retention_tombstone)은 DB에 존재하지만 doc 05(Security & Governance) 영역이라 여기서 제외한다.

transcript live tail + ingest backfill + OTel collector → raw_event(원본 보존) → observed_event → side-table(usage_facet · diff_hunk · verification_run) → ingest가 insight 파이프라인(detector 5종)을 직접 호출 → signal → 조회 시 on-demand SessionMetrics.

04ObservedEvent

Event-first: 메세지·디테일·raw 뷰와 모든 detector는 ObservedEvent + correlation 키(tool_use_id/request_id/turn_id/message_id)로 직접 동작한다. correlation 키는 nested object가 아니라 1급 컬럼이다. 상세: implementation-notes.html#event-first-redesign.

Correlation 키

  • tool_call ↔ tool_result 페어링: tool_use_id 컬럼.
  • API 요청 단위 묶음: request_id 컬럼.
  • 턴/메세지 묶음: turn_id / message_id 컬럼.
  • 서브에이전트 귀속·워크플로우 그룹: agent_id 컬럼(sidechain 이벤트의 개별 subagent 구분 — migration 0023) / workflow_run_id 컬럼(Workflow 팬아웃 run 단위 묶음 — migration 0024). turn_id는 run 진행 중 표류하므로 workflow 묶음의 결정론 키는 workflow_run_id다.
  • transcript 연쇄: event_uuid / parent_uuid.
  • OTel 상관: trace_id / span_id / parent_span_id 컬럼.

05File Lineage and VerificationRun

Transcript-only file lineage: DiffHunk rows are produced from the transcript toolUseResult.structuredPatch of Edit tool_result lines. Write tool_results carry structuredPatch=[] by design and produce zero rows. No filesystem watcher, no git poller, no commit-SHA-as-verification-marker. The structuredPatch shape is locked by a real-fixture invariant test.

DiffHunk

{
  "diff_hunk_id": "dh_…sha256…",
  "schema_version": "0.5.0",       // diff_hunk는 전역 SCHEMA_VERSION을 저장한다 (per-object 버전 아님)
  "session_id": "sess_real",
  "file_path": "/abs/path/src/service.ts",
  "change_type": "modified",       // added | modified | deleted
  "line_range_after_start": 42,    // post-image 기준; 빈 hunk면 둘 다 null
  "line_range_after_end": 57,      // (flat 컬럼 — nested object 아님)
  "introduced_by_event_id": "01J…(tool_result event_id)",
  "introduced_by_tool_use_id": "toolu_…",
  "patch_preview": " context\n-old\n+new\n",

  "parser_version": "verification_run@v1"

VerificationRun outcome resolution 체인

  1. OTLP tool_result log (success 신호) — measured.
  2. hook post_tool_use의 exit_code — measured.
  3. transcript "Exit code N" 라인 — measured. ③b <tool_use_error> 래퍼 → Failed(measured) — 단 Cancelled disposition은 예외.
  4. Unknown. 단, test/build/lint/format kind에 한해 Tier-4(estimated) 텍스트 규칙 적용 — looks_like_failure("error[", "FAILED" 등) 우선, 그다음 looks_like_success("test result: ok" 등 결정론 성공 요약). disposition 마커가 잡힌 result에는 Tier-4를 적용하지 않는다 (content가 실제 출력이 아님 — real fixture disposition_v01.jsonl).

status_basis 의미: exit = exit code 관측 경로, piped = non-pager로 파이프되어 exit code가 가려짐 — measured(exit) 판정은 불가하지만, 파이프를 통과해 남은 도구 자체의 결정론적 요약줄(test result: ok, Test Files … passed 등)이 있으면 Tier-4 estimated pass/fail로 해소한다(요약이 없으면 unknown 유지). status_basis는 그대로 piped로 남겨 exit 미관측을 투명하게 보존한다(2026-06-11 완화 — 종전엔 piped를 무조건 unknown으로 강제했다). 나머지 4종은 disposition 분류 — tool_result의 하니스 마커 prefix로 user_rejected(사용자 거부) / policy_denied(PreToolUse hook 차단) / cancelled(병렬 호출 취소) / background(백그라운드 전환)를 기록해 측정 불가 사유를 구분한다. tool_result의 is_error는 pass/fail 판정에 사용하지 않는다. status 값은 두 가지 측정 불가 사유를 구분한다: unknown = 명령이 실행됐으나 결과를 읽지 못함(exit/piped basis), not_executed = 명령이 실행되지 않음(disposition basis — 거부/차단/취소/백그라운드). 분리 이유: 비실행 run이 unknown에 섞이면 unknown이 단조 증가해 "측정 한계"의 신호가 흐려진다(2026-06-23).

06Signal

Facts only: Signal은 결정론 detector가 관측한 사실(facts)만 담는다. severity/confidence/claim 같은 판단(judgment) 필드는 저장하지 않는다.
{
  "signal_id": "sig_…",            // sha256(detector ‖ session_id ‖ sorted evidence_refs)[..12]
                                   // → 재실행 idempotent (INSERT OR REPLACE)
  "schema_version": "signal.v1",
  "session_id": "sess_…",
  "detector": "tool_failure",
  "subkind": null,                 // 선택적 사실 분류 (해석 아님)
  "summary": "factual summary — 판단 어휘 없음",
  "evidence_refs": ["01J…"],       // observed_event event_id 배열 — 비어 있지 않음은
                                   // detector별 테스트로 보장 (AC-4; DB CHECK 제약 아님)
  "facts": { },                    // detector별 사실 projection — severity/confidence 없음
  "provenance": { "detector": "tool_failure@v1", "version": "L1", "rule_pack": null },
  "created_at": "…"
}

provenance.version은 항상 "L1"(deterministic). rule_pack은 코드 기본 detector면 null, TOML rule pack 로드 시 그 id. 외부에서 signal에 쓰는 API는 없다 (no annotation model).

Detector 4종 (deterministic L1)

detectorEvidence requirement
tool_failurefailed tool result or OTel error event
risky_actiondestructive command, sensitive file/path, user_modified hunk 등 관측 사실
context_bloat대형/반복 출력 등 이벤트 기반 결정론 규칙
re_read동일 대상 반복 read 관측

detector manifest는 /v1/detectors와 MCP whats_in_my_cc.list_detectors로 노출된다.

07SessionMetrics, Usage & Fingerprint

SessionMetrics — on-demand (저장 테이블 없음)

GET /v1/sessions/:id/metrics 호출 시 side-table에서 매번 재계산한다. 합성 가능한 count만 반환한다 — window-고정 rate scalar는 반환하지 않으며, rate는 소비자가 자기 window로 계산한다. severity/판단/threshold 플래그 없음.

{
  "session_id": "sess_…",
  "tool_call_total": 124,
  "tool_failure_count": 3,          // tool_failure detector signal 수
  "verification_total": 9,
  "verification_passed": 7,
  "verification_failed": 1,
  "verification_unknown": 1,        // 측정 실패 — 실패가 아니다. pass/fail 분모에 넣지 말 것
  "context_bloat_count": 2,         // context_bloat detector signal 수
  "tool_user_rejected": 0,          // disposition 분류 (하니스 마커 prefix)
  "tool_policy_denied": 1,
  "tool_cancelled": 0,
  "tool_backgrounded": 2,
  "turn_duration_ms_total": 19115218,  // system/turn_duration 레코드 durationMs 합
  "turn_duration_count": 51,           // 평균은 소비자가 합/count로 계산
  "api_error_count": 0,                // system/api_error 레코드 수 (예: 529 overloaded)
  "api_rate_limit_count": 0,           // api_error 중 /error/status==429 (rate_limit_error) — 2026-07-04
  "input_tokens": 0,                   // usage facet 세션 합계 4종 — 할당량(rate limit budget)은
  "output_tokens": 0,                  //   로컬 관측면에 없어 사용량만 측정한다 (2026-07-04)
  "cache_read_input_tokens": 0,
  "cache_creation_input_tokens": 0,
  "estimated_cost_usd": 0.0,           // 공개 가격표 추정(estimate_public_pricing) — 실비 아님, 하한 추정

  "compact_boundary_count": 5,         // system/compact_boundary — 컨텍스트 압축 횟수
  "tool_result_truncated_count": 0,    // "... [N characters truncated] ..." 마커 포함 tool_result 수
  "user_interruption_count": 11,       // "[Request interrupted by user"로 시작하는 user_message 수
  "detector_firing": { "tool_failure": 3, "re_read": 1 }   // detector → signal 수
}

disposition count 4종은 실패도 unknown도 아닌 별도 축 — 실행되지 않았거나(거부/차단/취소) content가 실제 출력이 아닌(백그라운드) 호출의 결정론 분류다. session-facts 6종(turn_duration·api_error·compact_boundary·truncation·interruption)은 transcript의 결정론 마커·레코드에서 직접 세는 측정값으로, 전부 실 코퍼스 fixture(session_facts_v01.jsonl)에 잠겨 있다.

Usage — /v1/sessions/:id/usage

side-table usage_facet(assistant 출력 이벤트당 1행: model + 토큰 4종)에서 집계.

  • assistant_events: usage_facet 행 수. user_turns: 세션의 distinct turn_id 수(= 사용자 프롬프트 수).
  • 토큰 4종: input_tokens · cache_creation_input_tokens · cache_read_input_tokens · output_tokens.
  • billed_tokens = input + cache_creation + output (cache_read는 비과금).
  • estimated_cost_usd: 공개 단가 추정 — 실제 청구가 아니다. cost_basis="estimate_public_pricing" + pricing_version + models_without_pricing(가격 미상 모델은 합계에서 제외, UI에 공시).
  • by_model: 모델별 assistant_events·토큰·추정 비용·priced 플래그. user_turns는 세션 레벨이라 per-model 없음.
  • per-session cache_hit_ratio scalar는 반환하지 않는다 — 토큰 구성요소에서 소비자가 계산한다.

Usage baseline — /v1/usage/baseline

usage_facet가 있는 모든 세션 횡단 quantile(p25/median/p75): cache_hit_ratio · billed_tokens · assistant_events · output_tokens + session_count. cache_hit_ratio 분포는 baseline에만 존재한다 — 세션 횡단 quantile 분포는 유효한 비교다.

SessionFingerprint — GET /v1/sessions/:id/fingerprint (on-demand, 저장 테이블 없음)

"이 세션은 어떤 구성 아래에서 돌았는가"의 결정론 관측. 자기개선 루프의 독립변수 — 개입(스킬/모델/CC 버전 등 구성 변경)의 효과를 세션 코호트로 귀속한다. SessionMetrics와 동일한 on-demand 무저장 패턴이며 판단 필드 없음. 구현: src/insight/fingerprint.rs의 SessionFingerprint.

{
  "session_id": "sess_…",
  "models": ["claude-…"],                 // assistant_message payload `$.model` distinct (payload 필드 → 과거 세션은 재ingest 필요)
  "cc_versions": ["…"], "git_branches": ["…"],
  "cwds": ["…"], "entrypoints": ["…"]    // observed_event 컬럼 distinct
}

fingerprint 필드는 모두 transcript/observed_event에서 도출된다. (CLAUDE.md instruction 스냅샷 필드 claude_md/instruction_sha256은 hook collector 폐지로 2026-06 제거 — implementation-notes.html 참고.)

09Schema Migration Policy

  • Minor schema changes must preserve existing fields or provide derived compatibility view.
  • Parser version changes must be recorded on every ObservedEvent.
  • OTel schema drift must not break raw event preservation; unknown telemetry fields는 facet의 attributes JSON에 보존된다.
  • 현행 migration head는 0022.
  • payload 필드(tool_call.tool_name, assistant_message.model 등)는 JSON BLOB이라 schema migration 없이 추가된다 — 기존 이벤트에 채우려면 재ingest 필요.
