Data Model Spec

ObservedEvent, telemetry facet, graph, lineage, finding, resource, export bundle schema를 정의한다.

SchemasGraphEvidence

01Data Model Principles

  1. OTel-first: trace_id/span_id/metric/log reference는 나중에 붙이는 optional metadata가 아니라 correlation_keys와 telemetry facet의 핵심 field다.
  2. Source-preserving: normalized object는 항상 raw source reference를 갖는다.
  3. Evidence-linked: finding, hypothesis, quality summary는 evidence_refs 없이 존재할 수 없다.
  4. No annotation model: 사용자/외부 서비스가 finding에 correction, label, status를 쓰는 domain object는 정의하지 않는다.
  5. Schema versioning: 모든 top-level object는 schema_version과 provenance를 가진다.

07File Lineage and VerificationRun

Slice-10a — transcript-only file lineage: DiffHunk rows are produced from the transcript toolUseResult.structuredPatch of Edit tool_result lines. Write tool_results carry structuredPatch=[] by design and produce zero rows. No filesystem watcher, no git poller, no commit-SHA-as-verification-marker. The structuredPatch shape is locked by a real-fixture invariant test (see implementation-notes slice-10a).

11Schema Migration Policy

  • Minor schema changes must preserve existing fields or provide derived compatibility view.
  • Parser version changes must be recorded on every ObservedEvent.
  • Export bundles must remain interpretable using the schema version embedded in the bundle.
  • OTel schema drift must not break raw event preservation; unknown telemetry fields are stored under attributes.extra.
