wimcc · replay · 컴팩트 거터 (헤어라인 스파인)

거터를 12px로 — 폭은 고정, 본문 가시성은 회복

승인하신 거터 스윔레인 아이디어를 유지하되 폭 제약을 해결했습니다(4안 설계→3인 심사, 우승=헤어라인 스파인). 핵심 변경: 백그라운드 에이전트마다 컬럼을 늘리던 것(이전 3개 = 64px)을 그만두고, 고정 ~12px 거터 안에서 1px 헤어라인을 3px 피치로 묶는다 — 백그라운드 1개든 30개든 거터 폭은 그대로. 본문(메시지) 폭이 곧 회복된다. 시간축은 여전히 정직(메인 아이템 순서 불변).

핵심 폭 비교 — 같은 백그라운드 3개, 거터만 다르다

왼쪽: 이전(에이전트당 레인 컬럼, 64px). 오른쪽: 신규(헤어라인 묶음, 14px). 우측에서 회복된 ~50px가 전부 본문으로 간다.

백그라운드 겹쳐도 14px — 헤어라인 색으로 누가 도는지

백그라운드 여러 개는 헤어라인을 x=2·6·10px에 나란히. 어떤 메인 행을 가로지르는 헤어라인 수 = 그 순간 백그라운드 N개. 신원은 각 블록 헤더의 스와치+id로 재확인(접근성 백스톱).

01:42:10 Bash 행을 가로지르는 헤어라인 3줄 = 그 순간 백그라운드 3개. 거터는 여전히 14px.

대량 백그라운드 4개↑ — 회색 스파인 1줄 + ⟂N (히스테리시스로 깜빡임 방지)

헤어라인이 분간 안 되는 백그라운드 >3이면 거터를 중립 회색 1줄로 접고, 개수는 ⟂N 칩으로. 개별 신원은 (접힌) 블록 목록에서. 모드 전환은 그룹 단위 임계+히스테리시스(>3 진입, ≤2 복귀)로 스크롤 깜빡임 없음.

main⟂ 백그라운드 1102:03:14
fan-out wave dispatched, collecting …
main⟂ 백그라운드 902:03:40

대량 fan-out은 워크플로우로 묶이는 경우가 많아 그쪽 컨테이너 뷰가 담당. 거터는 "백그라운드 살아있음" 표시 + 개수만 — 폭은 끝까지 14px 고정.
합의(4안→3심사, 우승=헤어라인 스파인): 폭 일정(백그라운드 多→컬럼 아닌 3px 피치 묶음, dense는 회색 1줄+⟂N) · 제로 reflow(거터를 본문 밀지 않게 per-row 페인트, 가상화 앵커와 비충돌) · 색 단일 출처(hash(agent_id) → --wimcc-agent-color를 헤어라인·▢/✓·블록 보더에 공유 — 신규, 현재 서브에이전트는 violet 하드코딩) · 접근성 백스톱(거터는 차분한 장식, 신원은 블록 헤더 스와치+id).
데이터 정직성(real-data anchoring): 종료 ✓는 일단 구간(span) 끝에서 그린다. subagent_completed/duration_ms로 정밀화하려면 먼저 실 payload를 tests/fixtures/**/real/에 동결 + invariant 잠금(미동결 시 duration은 "파생" 표기). per-agent per-row 멤버십도 현재 모델에 없음 → concurrentBackground(행별 수)·concurrentMainCount(블록별)로 시작, 멤버십은 구현 시 추가.
